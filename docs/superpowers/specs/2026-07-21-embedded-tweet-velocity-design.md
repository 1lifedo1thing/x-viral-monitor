# 长文内嵌帖子流速与排行榜跳转设计

## 目标

在 X Article 长文中，把每个内嵌帖子视为独立帖子：显示其自身流速徽章、加入悬浮排行榜，并支持从排行榜滚动和高亮到对应内嵌卡片。长文母帖继续保留自身徽章和排行榜条目。

## 已确认页面结构

目标页面 `https://x.com/icycat/status/2033096808076030044` 中，长文母帖的 `article[data-testid="tweet"]` 内嵌了 3 个同类 `article` 节点。每个内嵌节点都有独立状态链接、发布时间和互动指标；当前只有母帖进入数据仓库和排行榜。

## 方案

1. 数据扫描继续使用现有 GraphQL 响应，不增加 DOM 文案解析。扫描母帖 `tweet_results.result` 时继续深入其中的嵌套 `tweet_results`，把内嵌帖按自身 ID 写入现有 `tweetDataStore`。
2. `getTweetIdFromArticle` 只读取归属于当前 `article` 的状态链接，忽略后代内嵌 `article` 的链接，避免母帖和内嵌帖互相认错 ID。
3. 徽章沿用现有 `renderBadges`、`computeScore`、tooltip 和 `.xvm-badge` 样式。因为现有遍历已经覆盖嵌套 `article`，数据进入仓库后无需新增组件。
4. 排行榜沿用现有 `collectRanked`、`findArticleByTweetId`、`setLink` 和滚动高亮逻辑。自作用域 ID 解析保证每个内嵌帖成为独立条目，并让点击命中对应内嵌卡片。
5. 缺少自身浏览量或发布时间的内嵌帖继续跳过，不借用母帖或其他帖子指标。

## 视觉与交互

- 不建立新设计系统，不新增视觉 token。
- 内嵌帖徽章与普通时间线帖子完全一致。
- 排行榜条目与现有条目一致；母帖和内嵌帖按各自流速正常排序。
- 点击内嵌帖条目后，页面滚动到卡片并使用现有高亮/连线反馈。

## 验证

- 回归测试：嵌套 `tweet_results` 会同时保存母帖和内嵌帖数据。
- 回归测试：母帖 ID 解析不会命中内嵌帖链接，内嵌帖能解析自身 ID。
- 回归测试：排行榜定位函数返回正确的内嵌 `article`。
- 全量测试与 `build:dist` 通过。
- Chrome 实测目标长文：3 个内嵌帖均显示各自流速；排行榜出现对应独立条目；点击每项能滚动和高亮正确卡片。

## 非目标

- 不为 X Article 新建专用排行榜或折叠层级。
- 不从本地化 aria-label 文案反解析浏览量。
- 不修改内嵌帖原生布局、内容或操作按钮。
